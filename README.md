# mini-terminal

Маленький терминал для Binance USDT-M Futures. Окно с одним свечным графиком и боковой панелью-скринером, больше ничего. Торговать из него нельзя, ключи API не нужны: используются только публичные данные.

Написан на C++17. Окно и ввод через GLFW (X11 и Wayland), интерфейс рисует Dear ImGui, сеть на IXWebSocket, JSON разбирает nlohmann/json. Делался под тайлинговые WM (sway, hyprland, i3), поэтому окну заданы app_id и class `mini-terminal`, а цена и процент выводятся в заголовок.

## Что внутри

График: свечи, SMA 288, панель объёма с разбивкой на покупки и продажи, линейка, легенда по свече под курсором. История подгружается влево по мере прокрутки. Последняя свеча обновляется живьём из сокета.

Скринер: раз в несколько минут опрашивает все USDT-пары с суточным оборотом от 1 млн, считает расхождение цены с SMA 288 и показывает таблицей. Если задать порог, при пересечении придёт уведомление через `notify-send`.

## Сборка

Нужны компилятор с C++17, CMake 3.16+, git, OpenSSL, nlohmann-json и GLFW 3.4 или новее. Если системного GLFW 3.4 нет, CMake скачает его сам, но тогда понадобятся dev-пакеты Wayland и X11.

Debian / Ubuntu:

```sh
sudo apt install build-essential cmake git pkg-config libssl-dev nlohmann-json3-dev \
  libgl1-mesa-dev libwayland-dev libxkbcommon-dev wayland-protocols \
  libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libnotify-bin
```

Arch:

```sh
sudo pacman -S base-devel cmake git openssl nlohmann-json glfw libnotify
```

Дальше:

```sh
git clone --recurse-submodules https://github.com/repixey/binance-mini-terminal.git mini-terminal
cd mini-terminal
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

Бинарник появится в `build/mini_terminal`. Установить в систему: `sudo cmake --install build --prefix /usr/local`.

Если клонировали без `--recurse-submodules`, догрузите зависимости командой `git submodule update --init --recursive`.

## Запуск

```sh
mini_terminal [ТИКЕР] [1m|5m|15m|1h|12h|24h] [--vsync] [--x11|--wayland]
```

Всё необязательно. Без аргументов откроется BTCUSDT на минутках. Порядок аргументов не важен.

`--vsync` включает вертикальную синхронизацию. По умолчанию она выключена, иначе на Wayland окно, скрытое за другим, может зависать в ожидании кадра. `--x11` и `--wayland` принудительно выбирают бэкенд; без них GLFW решает сам и при неудаче пробует остальные.

## Управление

| Действие | Что делает |
|---|---|
| Колесо мыши | масштаб по времени |
| ЛКМ и перетаскивание | прокрутка |
| Двойной клик | вернуться к последней свече |
| Shift + ЛКМ, тянуть | линейка: изменение цены, проценты, число свечей, время |
| Esc или обычный клик | убрать линейку |
| V | показать или скрыть панель объёма |
| Поле слева вверху | сменить тикер, Enter |

В скринере клик по строке открывает график этой пары, правая кнопка убирает пару из списка. Заголовки таблицы сортируют. Интервал у скринера свой, он не зависит от интервала графика. По умолчанию 5m, то есть SMA 288 равна последним суткам.

В поле добавления тикера можно писать просто `SOL`, суффикс USDT дописывается сам. Добавленные руками пары не вылетают при обновлении списка по объёму.

## Алерты

Поле `alert SMA %` принимает порог. `+5` сработает, когда цена окажется выше SMA на 5% и больше, `-3` когда ниже на 3% и больше. Пустое поле выключает алерты.

Повторно по той же паре уведомление не придёт, пока она не отойдёт от порога хотя бы на пятую часть. Первая загрузка после запуска или смены интервала всегда проходит молча, чтобы не получить пачку уведомлений на старте.

## Устройство

```
src/
  main.cpp        окно, главный цикл, разбор аргументов
  chart.cpp       отрисовка графика
  screener_ui.cpp панель скринера
  screener.cpp    фоновый опрос REST и логика алертов
  net.cpp         REST для истории и WebSocket для живых данных
  session.cpp     смена тикера и интервала, применение данных к свечам
  state.h         общее состояние
  types.h         структуры данных
  config.h        константы и лимиты
  util.cpp        форматирование и мелкие помощники
  worker.h        поток с очередью задач
```

Сетевые потоки не трогают интерфейс напрямую. Они складывают события в очередь под мьютексом и будят главный поток, который забирает их раз в кадр.

Для графика работают два потока: один под REST, другой управляет жизненным циклом сокета. Скринер ходит только по REST в своём потоке и с сокетами не связан.

## Про Binance

История берётся из `/fapi/v1/klines`, живые данные из `@aggTrade` и `@kline_<интервал>`. Фьючерсные стримы сейчас разнесены по путям, и код сначала пробует `/market`. Если за 20 секунд не пришло ни одного сообщения, он переключается на `/public` и переподключается.

Скринер старается не упираться в лимиты: запросы растянуты по времени равномерно, а при ответе 429 или 418 вся очередь встаёт на паузу по заголовку `Retry-After`. Один обход списка стоит порядка сотен запросов в вес, так что не стоит гонять рядом несколько копий программы с одного IP.

## Деплой

Скрипт `scripts/deploy.sh` подтягивает изменения, обновляет сабмодули, пересобирает и ставит бинарник в `/usr/local/bin`. Сначала склонируйте репозиторий на целевой машине, потом просто запускайте скрипт после каждого `git push`.

```sh
./scripts/deploy.sh
PREFIX=$HOME/.local ./scripts/deploy.sh
```

## Ограничения

Нужна сессия с графикой, это не консольная программа. На голом сервере без дисплея она не запустится.

Если в системе нет `notify-send`, алерты тихо не отправляются, всё остальное работает.

Время на графике показывается в локальной зоне системы.
